## Goal

`docs/plan_review_fixes_20260923.md` R7.8). Harden it so that a paper number that disagrees with the claims

`tests/unit/test_number_audit.py`, that runs the script via `subprocess` on small synthetic paper and ledger
files in `tmp_path`.

Read the script first and keep its interface: arguments, exit codes and output format. **New checks add
lines; they do not change the meaning of existing ones.**

## New checks

Each check gets its own fixture test, with one passing case and one failing case.

1. **Signed values.** A number printed with a sign (`+3.73`, `−0.94`; treat U+2212 as a minus) must appear with
   the same sign in the ledger.
2. **CI tuples.** An interval printed as `[a, b]` must appear in the ledger as the same tuple: the same two
   numbers in the same order, with the U+2212 normalisation.
3. **Forbidden wording.** Flag, with line numbers:
   - `matches`, `indistinguishable`, `explains` and `establishes`, when used of a result;
   - `pre-registered` or `registered` within the same sentence as a ledger id whose status is exploratory.

   The word list lives in one constant at the top of the script.
4. **Exploratory labels in the abstract.** Every ledger id cited in the abstract whose ledger status is
   exploratory must be labelled "exploratory" in the same sentence.
5. **Stated counts.**
   - The audit prints its own counts: numbers checked, ids cited, violations per check.
   - The paper must not state an audit count that differs from those. Look for a line matching
     `audit:` or `number audit` followed by a count.
