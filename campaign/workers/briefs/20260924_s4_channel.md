## Report keys

This layout is a contract. Unit S4-depth emits the same contrast-object layout, so keep this exactly.

**Every contrast object has:**
- `diff_pp`;
- `ci95_pp_scenario`, `ci95_pp_task`;
- `p_two_sided` (bootstrap, two-sided, at `threshold_pp`);
- `threshold_pp`;
- `n_pairs`;
- `metric`.

**Contrasts:**
- D0 = `takeover_k10 − advise_k10`;
- N = `advise_k10_neutral − advise_k10`;
- S = `show_k10 − advise_k10`;
- TN = `takeover_k10 − advise_k10_neutral`.

The top-level keys:

| key | contents |
|---|---|
| `limits.per_arm.<label>` | `n`, `n_limit`, `rate`, where limit is `error_type == "limit"`. Cover every label above, plus these dev campaigns: `hj13_planner_alone_cap81_20260923`, `hj17_prefix_c81_{bplus,zs}_m{6,9,11}_20260923`, `hj8_sft_plan_bplus_20260919`, `hj8_executor_alone_bplus_20260919` |
| `limits.split.{D0,N,S,TN}` | Pairs where either arm hit `limit`, and pairs where neither did. Each part gives `n`, `mean_diff_pp`, and `contribution_pp` with scenario and task CIs; the contributions sum to the whole. Add a `label` field: "post-treatment mechanism, not a corrected estimate" |
| `limits.as_zero.{D0,N,S,TN}` | A contrast object with every `limit` episode's `goal_pass` set to 0 in both arms |
| `content.<label>` for the three advice/show labels | `n_interventions`, `share_fenced_code` with a CI, `median_chars`, `copy_rate`, using b2_decomposition's definitions |
| `metrics.{D0,N,S,TN}.{goal_pass,tgc,sgc}` | Contrast objects. SGC is scenario-level: find how the repo already computes SGC (e.g. `j10_report.py`'s `sgc` block or the hj12 scripts), reuse it, and cite it in a comment. TGC is the per-task binary task-goal completion as already used in the repo |
| `latency.<label>` | Per-episode wall-clock (median, mean) and per-planner-call latency (median), from existing event timestamps. If the events carry no timestamps, give `{"status": "no_timestamps"}` and say so |
| `noop_floor` | If `--noop-campaign DIR` is given: `goal_pass`, `tgc` and `sgc` means with scenario CIs; else `null` |
| `by_fdr` | See below |
| `census` | From `campaign/campaign_index.json` and `docs/claims_ledger.md`: dev campaign count, distinct arm count, and ledger row counts by status (registered vs exploratory), with the status parsed from each row's status column |
| `inputs`, `settings` | As in S4-depth: dirs, counts, crash counts, `n_boot`, `seed` |

### `by_fdr`

Benjamini–Yekutieli with `cluster_inference.by_fdr` (committed; do not re-implement).
- **Family:**
  - every contrast object in this report whose `metric == "goal_pass"`;
  - if `--depth-report PATH` is given, every contrast object in that JSON (unit S4-depth's report, same layout)
    whose `metric == "goal_pass"`.
- **Output:** a list of `{id, source, diff_pp, p_two_sided, p_by, survives_0_05}`, where `id` is the dotted key
  path, plus `m`.
- **Rule:** a contrast without a p is listed and left out of m.
