line | status | figure), plus a correction note for HO-01. Dev data only.

**Why the indicator changed.** HO-01..HO-NI-03 split the cap-81 prefix family on the prefix arm's
`handoff_occurred` flag. That flag is `effective_m < n_source_actions` (src/sidekick/prefix_source.py:184),
while the loop suppresses the live phase only when the replayed prefix is terminal
(src/sidekick/systems/loop.py:743-756, `prefix_is_terminal` :172-180). A source episode that made no more
than m executed actions but did not finish therefore gets flag = false, and the executor still takes
over. h* is read from the prefix episode's own `events.jsonl` instead; the flag is kept everywhere as
`h_flag` and reported as a sensitivity.

**Computed values.** `campaign/results/j17_hstar_20260924.report.json`, written by
`scripts/analysis/j17_hstar.py` (rule in `scripts/analysis/handoff_control.py`; tests
`tests/unit/test_handoff_control.py`, `tests/unit/test_j17_hstar.py`). Settings: 10,000 percentile draws at
seed 20260924, scenario and task clusters, the same 14 campaign directories (1,197 episodes, 0 crashes)
and the same conventions as `campaign/results/j17_depth_fixes_20260924.report.json`, which the HO rows
cite. J12 power: `campaign/results/j12_power_dev_hstar_20260924.report.json` (`scripts/analysis/j12_power.py
--handoff hstar`); the committed flag-based `campaign/results/j12_power_dev_20260924.report.json` is not
overwritten, and `--handoff flag` reproduces it exactly (dev, power table and every per-contrast rate).
