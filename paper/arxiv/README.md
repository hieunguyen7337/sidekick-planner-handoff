# arXiv Publication Pipeline

This directory (`/mnt/hpccs01/home/n12194778/iaes/.claude/worktrees/plan-2026-09-15/paper/arxiv`) contains the automated build, quality assurance, and packaging pipeline for preparing publication-ready arXiv LaTeX submissions from Pandoc Markdown manuscripts.

---

## 1. Overview & Pipeline Flow

The pipeline executes the following stages:
1. **Markdown Compilation & Lua Filtering**: Converts Markdown manuscripts to LaTeX using Pandoc, stripping internal ledger IDs (`strip_internal.lua`), auto-sizing code blocks (`latex_prep.lua`), and formatting tables/environments (`latex_prep.lua`). Tables get a `\needlines` guard so short tables are not split.
2. **TeX & BibTeX Compilation**: Runs `pdflatex` (pass 1) $\rightarrow$ `bibtex` $\rightarrow$ `pdflatex` (repeats at least twice and up to 5 passes post-bibtex until labels and cross-references settle) in nonstop error-checking mode.
3. **Rendering & Visual QA**: Generates 60 DPI page rasterizations, multi-page contact sheets (`sheet_*.png`), and optional 110 DPI zooms.
4. **Verification & Secrecy Checks**: Audits logs for undefined citations, missing figures, unmapped Unicode characters, overfull boxes, and private paths/residual ledger IDs (`check_tex.sh`).
5. **Clean-Room Packaging**: Bundles the self-contained `.tar.gz` submission archive and performs a clean-room compilation test in an isolated directory (`package.sh`). The clean-room compile reruns pdflatex like arXiv does (2–4 passes).

## 5. Ledger ID Stripping & Residuals

- **Automated Removal**: `strip_internal.lua` automatically removes parenthetical internal ledger IDs (e.g. `(HJ-01)`), dropped internal tracking table columns, and internal metadata annotations.
- **Residual IDs**: IDs used directly as nouns in prose (e.g., *"In run HJ-01, we observed..."*) are deliberately left in place and logged as `RESIDUAL` in `strip_internal.log`. These are flagged as `FAIL` by `check_tex.sh` and must be rephrased directly in the source Markdown.

## 6. Paper-side conventions and knobs

- YAML `author` may be a string or a list of maps with `name`, `affiliation` (string or list) and `email`; each author is one column of the title block, and `pdfauthor` lists the names. arXiv refuses anonymous submissions and wants `Firstname Lastname`; `authors.txt` renders `Name (Affiliation), ...` for the form. Example:
  ```yaml
  author:
    - name: Jane Doe
      affiliation: Some University, City, Country
      email: jane@example.org
  ```
- YAML `footer:` sets the first-page footer note; the default is `Preprint.` (it does not claim peer review). Use `footer: "Preprint. Under review."` only if that is true.
- YAML `fontsize:` (default `11pt`).
- Headings keep their own numbers (`## 3. ...`); LaTeX numbering is off. The first `#` heading is dropped when it repeats the YAML title, and `##` then becomes `\section`.
- Captions: write `Table N: ...` as a paragraph directly above a pipe table, and `![Figure N. ...](figures/x.png)`; the label is printed from the text (bold), never twice. A `.pdf` next to a `.png` figure is used instead.
- A fenced code block whose first line starts `Table N:` becomes a caption paragraph plus a verbatim block whose font size shrinks to fit the text width.
- Every table (and a heading run directly above it) gets a `\needlines` guard so short tables are not split and headings are not stranded. A table estimated at more than `NEEDLINES_MAX` (12) lines gets a guard of `NEEDLINES_SPLIT` (8) lines and may split, with the header repeated; larger guards left pages 20-40 % empty.
- Code spans in headings stay pandoc `Code`, so the PDF bookmark keeps them (`2.4 Metrics, and the floor of goal_pass`).
- Header identifiers: only a heading whose text contained a ledger id gets a recomputed identifier; an explicit `{#sec:..}` is kept, so `[..](#sec:..)` links survive the strip.
- A bare `*` (e.g. `h*` twice in one paragraph) opens emphasis in pandoc markdown; write `h\*`. The check FAILs on `\emph{` groups that open on punctuation.
- The arXiv form fields are ASCII-only: build.sh extracts them with `-f markdown-smart` and folds them with `meta_ascii.pl`; the check FAILs on non-ASCII, on an abstract over 1920 characters, on an empty PDF Author, and on placeholder text in the printed bibliography.
- Every non-ASCII character must have a `\newunicodechar` line in `template.tex`; build.sh fails and names the missing code point otherwise.
- `package.sh` refuses when `check_report.txt` ends in `CHECK: FAIL`; `FORCE=1` overrides it (for shake-down runs only). The clean-room compile reruns pdflatex 2–4 times, as arXiv does, with a fresh `HOME`, no `TEXMFHOME` and no shell escape, and FAILs on errors, undefined references, missing files, missing characters or a page-count change. A second clean room compiles the tarball on TeX Live 2025 (arXiv's default; the build is TL2026) when `$PUBTOOLS/tl2025` exists (`TL2025=0` skips it). Clean rooms are deleted on exit (`KEEP_CLEAN=1` keeps them).
- The check fails on ledger ids used as nouns in prose and on repository paths: those need a markdown edit, the filter deliberately leaves them (see `strip_internal.log` RESIDUAL lines). It also fails on placeholder text, campaign names (`j8_frontier`) and registration labels (`hj12`), and warns (per category, with pages) on short labels such as `J10`/`LP-2` not declared in `public_labels.txt`, commit-like hex strings, `lines N-M` references and repository file names. Each main.tex hit carries `[md:LINE]`, and the report ends [6/8] with a per-markdown-line edit list.
- `tex-gyre` must be installed (TS1 metrics for newtx); the installer's package list now includes it.
